DEEP DIVE

기억해야 할 일곱 가지

구두 평가에서 명령을 원리와 연결하는 압축 튜토리얼입니다.

1. 브랜치는 복사 폴더가 아니라 포인터다

커밋은 스냅샷이고 브랜치는 최신 커밋을 가리키는 이동 가능한 이름입니다. 실제 네 기능도 각 계정의 작은 feature 브랜치로 분리했습니다.

cd "$UPSTREAM_CLONE"
git switch main
git pull --ff-only
git switch -c feature/<github-account>-<topic>

2. Git의 세 공간이 reset을 설명한다

작업 디렉터리는 편집 중인 파일, index는 다음 커밋 후보, 히스토리는 완료된 커밋입니다. reset --soft는 포인터만 이동하고 index는 유지합니다.

cd "$UPSTREAM_CLONE"
git status
git diff
git diff --staged
git reset --soft HEAD~1

3. PR은 품질 관문이자 의사결정 기록이다

What은 변경 내용, Why는 해결할 문제, How는 검증 방법입니다. Issue와 리뷰가 연결되면 나중에도 변경 맥락을 재구성할 수 있습니다.

마커가 사라진 것은 문법적 병합이 끝났다는 뜻일 뿐입니다. 논리 충돌은 자동 병합 후에도 숨어 있으므로 양쪽 Issue의 완료 조건을 다시 확인합니다.

cd "$UPSTREAM_CLONE"
git status
git diff --check
python3 src/main.py

5. 원격 원본과 추가 예시를 분리한다

dave17code의 reverse_string, heeyoung35의 count_words, OliverJoo의 remove_duplicates, hyunn9799의 is_even은 원격의 실제 독립 모듈입니다. 원격과 동일한 src/main.py는 앞의 두 함수만 실행합니다. 네 함수를 한 번에 실행하는 코드는 원본을 바꾸지 않고 추가 학습 예시로 분리했습니다.

python3 src/main.py                 # 원격 main.py: 두 함수
python3 examples/team_utils_demo.py # 추가 예시: 네 함수

6. 증빙은 작업 직후 기록한다

Issue, PR, 리뷰 답글, 커밋 해시는 시간이 지나면 찾기 어렵습니다. 작업마다 SUBMISSION 인덱스를 갱신해야 누가·무엇을·왜·어떻게·무엇으로 검증했는지 설명할 수 있습니다.

cd "$UPSTREAM_CLONE"
git log --oneline --graph --all
