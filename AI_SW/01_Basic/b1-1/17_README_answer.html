QUESTION 01

SSH 포트가 20022이고 Root 원격 접속이 차단되었는가?

관련 파일 · 06 설정 · 04 설치 · 14 검증

답변

Port 20022와 PermitRootLogin no를 sshd drop-in에 설치합니다. 파일만 보지 말고 최종 해석과 실제 리슨을 함께 확인합니다.

sudo sshd -T | grep -E '^(port|permitrootlogin) '
sudo ss -ltnp | grep ':20022'

QUESTION 02

방화벽이 활성화되고 20022/tcp와 15034/tcp만 허용되는가?

관련 파일 · 04 설치 · 14 검증

답변

UFW 기본 인바운드는 deny, 허용은 SSH 20022와 APP 15034 두 개입니다. 새 VM에서 sudo ufw status verbose로 active와 추가 ALLOW 규칙 부재를 확인합니다.

QUESTION 03

세 계정과 두 그룹이 역할대로 구성되었는가?

관련 파일 · 04 설치 · 14 검증

답변

admin/dev/test는 모두 agent-common, admin/dev만 agent-core입니다. test가 core에 들어가면 키와 운영 로그 격리가 깨집니다.

id agent-admin
id agent-dev
id agent-test

QUESTION 04

Boot Sequence 5단계 [OK]와 Agent READY가 출력되는가?

관련 파일 · 05 환경 · 10 실행 · 03 Docker

답변

일반 사용자, 환경 변수, secret.key, 15034 사용 가능, 로그 쓰기 권한이 모두 맞아야 합니다. 설치 후 경로의 run_agent.sh로 실행합니다.

QUESTION 05

monitor.sh가 프로세스/포트를 검사하고 실패 시 exit 1인가?

관련 파일 · 11 모니터 · 14 검증

답변

pgrep -x agent_app으로 제공 앱 이름을 정확히 찾고, ss -ltnH로 15034 LISTEN을 별도 검사합니다. 둘 중 하나라도 없으면 오류를 stderr로 남기고 1로 종료합니다.

QUESTION 06

monitor.log가 고정 포맷으로 누적되는가?

관련 파일 · 11 모니터 · 14 검증

QUESTION 07

cron 매분 실행으로 로그가 자동 증가하는가?

관련 파일 · 07 cron · 11 모니터 · 15 증거

답변

agent-admin crontab이 절대 경로로 monitor를 실행합니다. 실행 전후 wc -l 값을 70초 간격으로 비교합니다. 앱이 실행 중이어야 health check가 성공합니다.

QUESTION 08

10MB/10개 로그 관리가 설정되었는가?

관련 파일 · 11 모니터 · 08 logrotate

답변

활성 로그가 10MiB를 넘으면 monitor.log.1로 회전하고, 최대 .9까지 둡니다. 활성 1개 + 백업 9개 = 총 10개이며 logrotate 정책도 함께 설치합니다.

항목 2 · 구현 설명

QUESTION 09

pgrep과 ss를 선택한 이유는?

관련 파일 · 11 모니터 · 05 환경

답변

pgrep -x는 이름 전체가 agent_app인 프로세스만 찾아 긴 셸 명령 문자열의 오탐을 피합니다. ss는 현대 Linux 기본 소켓 도구이며 LISTEN TCP만 숫자로 확인할 수 있습니다. 프로세스 생존과 네트워크 준비는 서로 다른 상태이므로 둘 다 필요합니다.

QUESTION 10

CPU/MEM/DISK는 어떻게 계산하고 왜 포맷을 고정했는가?

관련 파일 · 11 모니터 · 12 리포트

답변

CPU는 /proc/stat 두 시점 차이, MEM은 MemTotal - MemAvailable, DISK는 df -P /를 사용합니다. 고정된 key:value 포맷은 awk나 로그 수집기가 추측 없이 파싱하게 합니다.

QUESTION 11

agent-dev 소유, agent-admin 실행 권한은 어떻게 만족하는가?

관련 파일 · 04 설치 · 11 모니터 · 07 cron

답변

agent-dev:agent-core 750입니다. 소유자는 rwx, 그룹은 r-x, 기타는 ---입니다. admin은 core 그룹원이라 수정 없이 실행할 수 있습니다.

QUESTION 12

10MB/10개 회전 로직은 어떻게 구현했는가?

관련 파일 · 11 모니터 · 08 logrotate · 13 보존

답변

stat -c %s로 크기를 재고 높은 번호부터 역순으로 이동합니다. 역순이어야 기존 백업을 덮어쓰지 않습니다. 마지막에 활성 로그를 .1로 옮기고 빈 활성 파일을 만듭니다.

항목 3 · 설계 이유

QUESTION 13

SSH 포트 변경과 Root 차단의 위험 모델은?

관련 파일 · 06 SSH · 04 설치

답변

비표준 포트는 자동 스캔 소음을 줄이는 보조 수단입니다. Root 차단은 인증 하나가 뚫려 곧바로 최고 권한을 얻는 경로를 없애고, 일반 계정 + sudo로 사용자별 감사 흔적을 남깁니다. 공개키 인증과 업데이트를 대체하지는 않습니다.

QUESTION 14

api_keys와 로그를 agent-core로 제한한 이유는?

관련 파일 · 04 설치 · 14 검증

답변

QA는 업로드 파일 시험이 필요하지만 비밀 키와 운영 로그는 필요하지 않습니다. 필요한 역할에만 권한을 주면 계정 침해 시 피해 범위가 작아집니다. 이것이 최소 권한과 폭발 반경 축소입니다.

QUESTION 15

경고와 즉시 종료 항목을 왜 나누는가?

관련 파일 · 11 모니터

답변

프로세스/포트 실패는 서비스 불가이므로 exit 1입니다. 높은 CPU/MEM/DISK나 방화벽 조회 실패는 위험 신호지만 데이터 수집을 계속해야 추세와 원인을 남길 수 있으므로 WARNING 후 진행합니다.

QUESTION 16

>와 >>의 차이는?

관련 파일 · 07 cron · 09 보존 cron

답변

>는 덮어쓰고 >>는 파일 끝에 추가합니다. 모니터링은 시간 변화가 핵심이라 이전 기록을 보존하는 >>가 필요합니다.

항목 4 · 응용 상황

QUESTION 17

Nginx로 대상이 바뀌면 무엇을 변경하는가?

관련 파일 · 05 환경 · 11 모니터

답변

프로세스 식별, 포트(80/443), access/error 로그, www-data 권한을 바꿉니다. 실제 HTTP 응답을 확인하는 curl /health도 추가해야 “살아 있지만 500만 반환”하는 상태를 잡습니다.

QUESTION 18

프로세스는 살아 있는데 포트가 안 열리면 어떤 순서로 보는가?

관련 파일 · 10 실행 · 11 모니터 · 15 증거

답변

QUESTION 19

로그 폭증과 디스크 포화 위험의 단기/중기/장기 대응은?

관련 파일 · 11 모니터 · 08 logrotate · 13 보존 · 09 cron

답변

단기: df/du로 범인을 찾고 안전한 회전 로그부터 압축·이동합니다. 중기: logrotate, 단계 경보, 오류 재시도 폭주를 고칩니다. 장기: 일일 로그량과 보존 기간으로 용량을 계획하고 중앙 수집·아카이브·삭제 정책을 둡니다.

개념 튜토리얼 · 현실 비유로 연결하기

작은 카페 = 서버
  • SSH: 직원 출입문
  • UFW: 열어 둘 문을 정하는 경비 규칙
  • 사용자/그룹: 직원증과 부서
  • 프로세스: 일하는 바리스타
  • 포트: 주문 창구
  • 로그: 주문·사고 장부
  • monitor.sh: 매분 순찰하는 매니저
  • cron: 매니저의 알람

프로세스와 포트를 둘 다 보는 이유

바리스타가 건물 안에 있어도 주문 창구가 잠겨 있을 수 있습니다. 프로세스 존재는 프로그램 생존, 포트 LISTEN은 네트워크 준비를 뜻합니다.

750 권한 읽는 법

대상숫자권한
소유자 agent-dev7=4+2+1rwx
그룹 agent-core5=4+1r-x
기타0---

CPU 계산 예시

첫 측정 전체 10,000/idle 7,000, 다음 측정 전체 10,100/idle 7,060이면 전체 증가 100 중 일한 시간은 40입니다. CPU 사용률은 40%입니다.

cron이 터미널과 다른 점

cron은 PATH와 환경 변수가 적고 현재 디렉터리도 다를 수 있습니다. 그래서 절대 경로, 별도 환경 파일, stdout/stderr 로그가 중요합니다.

회전과 보존

회전은 상자가 무거워지면 새 상자를 여는 일이고, 보존은 7일 지난 상자를 압축해 창고로 옮기고 30일 뒤 폐기하는 일입니다. 크기와 시간이라는 서로 다른 문제를 해결합니다.
