## 선택 과제 및 추가 작성물

선택 과제 세 가지는 [BonusDataAnalyzer](../src/bonus_pipeline.py)가 기본 클래스를 상속하여 구현했다. 이미지 고급 피처는 PDF가 허용한 두 방법 중 엣지를 선택했다. 가입 월 코호트 히트맵과 Plotly RFM 차트도 [별도 노트북](../notebooks/bonus_report.ipynb)에 분리했다.

README의 Mermaid 도식, 개념·코드 설명 MD와 HTML, TDD 테스트 기록은 과제 설명과 검증을 위한 자료로 작성했다. 웹 서비스·데이터베이스·인증·배포·머신러닝 모델 같은 별도 제품 기능은 추가하지 않았다.

## 금지 항목 점검

- 이미지 평균·표준편차·엣지는 NumPy로 계산했다. OpenCV/Pillow를 import하거나 이미지 처리에 사용하지 않았다.
- Scikit-learn, NLTK, pandas-profiling, sweetviz를 사용하지 않았다.
- Plotly는 선택 과제 3의 `plot_rfm()` 안에서만 import했다.
- 기본 분석의 직접 외부 의존성은 NumPy/Pandas/Matplotlib/Seaborn이다. unittest는 표준 라이브러리이며 Jupyter 관련 패키지는 노트북 실행 도구로 분리했다.
- Matplotlib 등 설치된 라이브러리의 내부 의존 패키지 존재를 직접 이미지 처리에 사용한 것으로 보지 않았다. 프로젝트 분석 코드에서 금지 라이브러리를 직접 호출하지 않는지 확인했다.

## 다시 확인하며 정리한 사항

1. 노트북은 PDF 2쪽이 경로까지 지정한 필수 결과물이라 유지했다. 분석 로직은 `.py`에 두어 노트북 없이도 테스트할 수 있게 했다.
2. 상품 단가를 클리핑한 뒤 매출까지 다시 계산하면 RFM이 달라지므로 원래 `amount`를 보존했다.
3. 이미지 표준편차는 `ddof=0`, 거래 통계는 `ddof=1`인 점을 문서에 명시했다.
4. 코호트 분모를 첫 달 구매자 수로 잘못 잡지 않고 가입 월 고객 수로 계산했다. 늦은 첫 구매는 재구매에서 제외하고 미래 월은 NaN으로 표시했다.
5. 공개 거래 표본의 구매 이력을 고객 단위로 유지했다. 한 주문에 여러 상품 행이 있어 F를 고유 주문 번호 수로 수정하고 실패→통과 테스트를 남겼다. 보너스 합성 샘플의 균등 고객 유형은 실제 분포로 일반화하지 않았다.
6. 실행하지 않은 캠페인을 성과로 기록하지 않고 기대 효과와 검증에 필요한 데이터를 포함한 제안으로 구분했다.

## 실행 검증

Python 3.12.2 / conda py312에서 [테스트 18개](../reports/tests_final.txt)가 통과했고, [기본·보너스 노트북](../reports/notebook_execution.txt)을 모두 실제 커널에서 실행했다. Red/Green 기록은 [reports](../reports/)에 보관했다. 공개 원본 가격×수량과 amount가 일치하고, 상품 행 22,488개·주문 1,038개·양의 구매액 521,978.13 GBP가 유지되는지 통합 테스트로 확인했다.

GitHub URL 제출은 아직 수행하지 않았다. 원본에 상품 사진과 가입일이 없어서 이미지 계산에는 보조 배열, 가입 코호트에는 별도 합성 샘플을 사용했다. 실제 상품 사진의 피처와 실제 가입 고객의 유지율을 분석한 것으로 주장하지 않았다.


## 문서와 시각화 확인

- 기본 6종 차트와 보너스 코호트 히트맵을 이미지로 확인했다. 박스플롯은 중앙 구간이 보이도록 가격 축을 로그 눈금으로 표시했다.
- 설명 HTML은 diagram-design의 self_check와 geometry 검사에서 문제가 없었다. 흐름도는 원문 6단계·5개 연결을 유지했고 상속도는 두 클래스와 부모 방향을 표시했다.
- Chrome에서 데스크톱/모바일 가로 넘침이 없고 내부 목차 링크가 연결됨을 확인했다. Plotly 4개 그룹·240개 점과 범례 선택 동작도 확인했다. [브라우저 검사 기록](../reports/html_verification.txt).
- Markdown의 상대 파일 링크와 코드 행 링크가 실제 파일 범위 안에 있는지 확인했다. 입력/결과 CSV는 루트 .gitignore의 예외 규칙으로 제출 대상에서 빠지지 않게 했다.
