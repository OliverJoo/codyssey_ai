# Mini NPU Simulator

## 프로젝트 개요
패턴 행렬과 필터 행렬의 MAC(Multiply-Accumulate) 점수를 계산해
입력 패턴이 어떤 필터와 더 유사한지 판별하는 시뮬레이터입니다.

- 모드 1: 사용자가 직접 `3x3` 필터 2개와 패턴 1개를 입력
- 모드 2: `data.json`의 `5x5`, `13x13`, `25x25` 데이터를 자동 분석

## 파일 구성
- `main.py`: 모드 선택 및 전체 실행 진입점
- `mode1.py`: `3x3` 사용자 입력 처리
- `mode2.py`: `data.json` 자동 분석 및 결과 요약
- `mac.py`: MAC 계산, 점수 비교, 시간 측정
- `label.py`: 라벨 정규화 (`+`, `cross`, `x` -> `Cross`, `X`)
- `data.json`: 필터/패턴 테스트 데이터

## 실행 방법
```bash
python3 main.py
```

실행 후 아래 두 모드 중 하나를 선택합니다.

```text
1. 사용자 입력 (3x3)
2. data.json 분석
```

## 동작 방식
각 위치의 값을 곱해서 모두 더한 MAC 점수를 사용합니다.

```text
score = sum(pattern[i][j] * filter[i][j])
```

- 모드 1: `A`, `B` 두 필터 점수를 비교
- 모드 2: `Cross`, `X` 두 필터 점수를 비교
- 점수 차이가 `1e-9` 미만이면 동점으로 처리
  - 모드 1 결과: `판정 불가`
  - 모드 2 결과: `UNDECIDED`

## 모드 1
사용자가 `3x3` 필터 A, 필터 B, 패턴을 한 줄씩 공백으로 입력합니다.

- 각 줄은 정확히 3개의 숫자여야 합니다.
- 숫자가 아니거나 개수가 맞지 않으면 해당 줄을 다시 입력받습니다.
- 출력 항목:
  - A 점수
  - B 점수
  - 평균 연산 시간(10회 기준)
  - 연산 횟수(`N^2`)
  - 최종 판정

## 모드 2
`data.json`의 필터와 패턴을 읽어 자동으로 점수를 계산하고 `PASS`/`FAIL`을 판정합니다.

- 필터 키: `size_5`, `size_13`, `size_25`
- 패턴 키 예시: `size_13_1`
- 기대 라벨은 `normalize_label()`로 정규화 후 비교
- 행렬 크기가 맞지 않거나 필수 키가 없으면 해당 케이스는 `FAIL`

## 실패 원인 분석
1. 동점 처리
   `size_13_1`은 두 점수 차이가 `1e-9`보다 작아서 `UNDECIDED`가 되며, 현재 규칙상 `PASS`로 인정되지 않습니다.

2. 입력 형식 오류 가능성
   모드 1에서는 숫자 개수 불일치 또는 숫자 변환 실패 시 재입력을 요구합니다.

## 복잡도 분석
MAC 계산은 모든 원소를 한 번씩 순회하므로 시간 복잡도는 `O(N^2)`입니다.

| 크기 | 평균 시간(ms) | 연산 횟수(N²) |
|---|---:|---:|
| 3x3 | 0.000508 | 9 |
| 5x5 | 0.000917 | 25 |
| 13x13 | 0.004629 | 169 |
| 25x25 | 0.015475 | 625 |

- `for row`, `for col` 이중 반복으로 전체 원소를 순회합니다.
- 입력 크기가 커질수록 실행 시간도 대체로 `N^2`에 비례해 증가합니다.
- 현재 성능 표는 코드의 10회 평균 측정값 기준입니다.
